# 天地星AI 1627071163：兼容验证说明

这不是完整兼容层的成功声明。实现优先沿用原生 Bot VM，在标准 dota/default heroes 上启用思考；游廊侧只负责配置和准备。若该路线不成立，需要实测后逐项设计真实适配，不伪造 API、不回退默认 AI。

## 阶段一：文件和静态候选

面板沿用1.2 Workshop下载器。必须真实下载并锁定归一化SHA；不能从名称猜版本。扫描器不执行下载代码，识别常见原生入口、显式回调声明、已知Bot全局调用以及字面 require/dofile，标记动态模块路径/非UTF8。

这是保持字符串/注释偏移的轻量词法扫描，不是Lua解析器、类型系统、安全审计或完整依赖解析。局部遮蔽可能误报全局，对象方法、动态选择、赋值形式回调、间接调用可能漏报。静态报告始终 runtime_verified=false。

## 阶段二：部署副本与原生入口探针

源码库不改。准备开服时在事务暂存副本插入会话标记和存在性探针，纳入部署SHA后提交。每次进程启动随机session，重试也换session。原始AI的异常不被吞掉；函数返回值/原始代码体不被包装替换，probe自身以pcall保护。

支持 `function Think(...)` 等显式声明内的轻量计数。`Think = function(...)` 暂不插入回调计数，但入口仍可能有探针。顶层return后的代码不会追加。特殊编码或未识别入口拒绝/提示，不猜测并假称已验证。

事件协议：`LANLAB|<本次32位hex session>|<kind>|<detail>`。

| kind | 内容 | 正确解读 |
|---|---|---|
| CAPS | addon_server_vm_not_native_bot_vm 中函数缺失列表 | 游廊VM与BotVM不同；这里缺GetBot不证明原生VM缺失 |
| BOT_ENTRY | 文件名:loaded | 引擎实际执行了某个部署入口 |
| BOT_API | 文件名:present 或缺失名称 | 只覆盖扫描候选全局，不覆盖全部对象方法 |
| BOT_CONTEXT | 文件名:bot_handle/no_handle/GetBot_missing | 此时调用GetBot的结果；选择阶段可没有英雄句柄 |
| BOT_CALLBACK | 文件名:回调名:计数 | 第1/64/1024及每8192次报告；按入口取最大观测，不是全体总计 |
| FILL | 请求及实际bot数量 | 数量不等于AI行为正确 |
| ERROR | 准备推进、API/身份、填充等异常 | 保留日志、停止该局、定位具体问题 |

当前输出是可诊断日志，不是防伪attestation。第三方Lua有正常游戏脚本权限，文件哈希不能把不可信作者变成沙箱安全代码。只使用可信来源；不得把探针当作能防作弊的机制。

## 阶段三：真实行为矩阵

复制 `compat/acceptance.template.json` 到外部 evidence目录。记录Linux Dota buildid、两客户端buildid、addon source SHA、UI source SHA、client revision、Workshop内容SHA、CT资源与内核/LXCFS来源。每次改源码或脚本都重新记录。

| 检查 | 必须保留的观察 |
|---|---|
| 两端真实连接 | 两台原版客户端加入同一LXC进程，无会话拒绝 |
| 等待与权限 | 无人点开始不推进，权限与准备状态真实同步 |
| 脚本运行 | 当前session的真实Bot入口/回调，非fixture或控制台echo |
| 英雄与队伍 | 双方人数与英雄正确，无默认AI静默替代 |
| 购买/技能 | 能买装备、升级和释放技能，无持续Lua异常 |
| 位置 | 与配置意向相比实际走线；未适配时明确FAIL/BLOCKED |
| 团队行为 | 对线、撤退、支援、目标选择符合脚本实际表现 |
| 完整比赛 | 胜负、结束、进程重开后回到干净准备状态 |
| 更新/回滚 | 下一局换SHA、当前局不变、回滚正确 |
| 卡顿改善 | 同版同AI同数量的帧时间尖峰/核心负载对比；随后关闭探针复测 |

不接受“绿色进程”“下载成功”“英雄在移动”“出现一次GetBot”“模拟测试全绿”作为完整兼容PASS。既不因旧教程缺失就断言不可行，也不为交付承诺未经测量的兼容。

## 特别边界

当前意向位置没有转换成天地星依赖的原生房间槽位。不提供两侧不同脚本或自定义地图。默认选人/标准模式不等于所有官方模式精确复刻。原生Bot路线失效时源码不会自动生成简陋AI替代；按真实缺失接口再开发适配。

尽可能先用关闭Bot的阶段验证连接，再启用原生探针，再观察真实AI，最后关闭探针做性能对比。不要同时改变引擎启动方法、UI、机器人版本和模式，让问题无法归因。
