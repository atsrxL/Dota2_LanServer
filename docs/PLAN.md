# 项目计划书

版本：1.0.0。编制日期：2026-09-16。对象：一台 PVE x86_64 主机上的单实例 Dota 2 LAN 服务器。

## 一、目标及验收定义

交付可审查、可重跑、可继续开发的源码包。自动创建 Ubuntu 24.04 非特权 LXC，固定 6 vCPU、6 GiB 内存、250 G rootfs；网页控制 SteamCMD 与游戏进程；提供中文帮助、测试证据及 Codex 接手说明。

成功分为五层：A. 脚本语法/业务测试通过；B. 实际 PVE 创建与环境配置成功；C. 真实 Steam 授权与 App 570 安装成功；D. 当日 Linux 二进制在 LXC 内稳定启动；E. 至少两台实际客户端连接并完成测试对局。本交付附带的是 A 层证据，B～E 必须在目标机器实测后填写，不合并为笼统“部署成功”。

## 二、技术方案与配置

| 项目 | 设计 |
|---|---|
| 容器 | Ubuntu 24.04 amd64、非特权、nesting=0 |
| CPU | pct --cores 6；不是承诺独占物理 CPU |
| 内存 | pct --memory 6144；固定 6 GiB |
| 磁盘 | pct --rootfs <storage>:250；不预估或锁定上游游戏实际大小 |
| Swap | 1024 MiB 额外额度，可改 0；有效性受宿主 swap/cgroup 影响 |
| 网络 | vmbr0 为示例，可选 VLAN；DHCP 或静态 IPv4；IPv6 不自动配置 |
| 游戏 | SteamCMD App 570、优先 Valve dota.sh、缺失时用 Linux 二进制 |
| 管理入口 | Nginx HTTP :8080（免登录、无面板密码）、LAN 白名单 |
| 网页后端 | Python WSGI + Waitress；静态 HTML/CSS/JS，无前端构建 |
| 运行代理 | Python + pexpect，Unix socket，独立 systemd 服务 |
| 状态 | 原子 JSON；任务历史 100 条；配置备份 20 份 |
| 日志 | 4 MiB 轮转 + 一个旧分片；每个任务独立日志 |

## 四、关键风险及处置

Steam 登录/2FA 改动：使用交互 PTY、一次性输入、手机批准提示；保留控制台首次登录退路。不移除 Steam Guard，不把密码加入 argv/环境文件。

Valve 更新改变运行依赖/地图/认证：集中在 `build_command()` 和 SteamJob 适配；先收集日志、manifest、依赖，再按实际报错调整。不下载第三方 dedicated.so、不绕过授权、不直接改特权容器。

6 GiB 内存：遵守用户给定规格，但不保证全部自定义地图/机器人数量在该额度内；监视 cgroup memory.events、游戏退出信号和 PVE 内存图；优先排查模式负载而非悄悄加内存。

250 G 磁盘：配置为整个 CT 的 rootfs 容量，含 OS、应用、Steam 缓存与日志；Steam 更新可能同时保留旧/新块。初装空闲阈值 100 GiB、后续更新 20 GiB 只是保守下限，不保证适配未来 depot 大小；不自动清除游戏资源。

更新中断：更新前建立维护标记，成功日志 + manifest StateFlags=4 + Linux 启动入口共同通过后才解除；取消/失败/代理重启后保持阻止开服。服务器原先运行时，只有用户明确授权才停服，成功后是否恢复也由用户指定。

LAN 安全：Nginx 白名单与每 CT PVE 规则双层；不会自动开启全局防火墙，需现场检查。无公网映射、无任意 Shell、无 RCON 服务；HTTP 明文且无面板认证，只能使用可信 LAN。

## 五、回滚与维护

代码与数据分离。环境部署失败保留 CT，使用 provision-existing 重试。更新代码前主动结束任务与停服，然后做 PVE 备份。配置快照只能回滚设置，不能回滚游戏版本/运行中的比赛。全量 PVE 备份可包含 Steam 登录缓存，应限制访问或加密。

面板自启动不等于自动开服。游戏自动开服默认关闭；可以在确认稳定后启用。只重启网页后端不会影响运行代理。升级代理意味着计划停服。

## 六、后续扩展顺序

优先完成真实 App 570 与两台客户端验收，然后再考虑精确 A2S 就绪度/玩家数、特定 Workshop 地图适配、操作审计导出。定时更新应先有可靠的空服判断与 Steam 授权策略，不能只加一个盲目重启 cron。公网、多租户、多实例不在本版安全范围内。
