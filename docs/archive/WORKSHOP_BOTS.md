# Workshop 机器人脚本管理 · 1.2.0 本地候选版

## 这版做了什么

网页输入单个 Workshop ID → 服务端查询 Valve 元数据 → SteamCMD 授权下载 → 检查/解包 → 保存不可变版本 → 选择下一局 → 下次启动前部署。默认输入 `1627071163`，预期条目是“天地星AI · 固定搭配”，真正的名称、App 与标签在任务中读取，不以预填提示代替核验。

这版没有读取 Dota 原生房间，没有 GC 账号控制器，也没有同步房间的玩家、站位、模式或双方不同 Bot。它不是完整的“原生房间配置桥接”。先验证当前脚本在 Linux Dedicated 上真正运行，再接入房间配置读取。

面板仍是 HTTP 8080、无面板密码登录；保留 CPU/每核心/内存监控与 LAN/Host/Origin/CSRF 防护。LXC 目标保持 6 vCPU / 6 GiB / 250 G，不改变现有资源。

## 使用顺序

1. 升级前先结束任务并停服。已有容器使用项目的 provision-existing.sh，不重新创建或删除 CT。具体见 CODEX_WORKSHOP_HANDOFF.md。
2. 进入 HTTP 面板的“SteamCMD”，填写并保存 Steam **登录账号名**，按原流程完成账号/Guard 授权；先安装真实 Dota 2。
3. 进入“机器人脚本”，输入 `1627071163`。“核对条目信息”只查公开元数据，不需要输入 Steam 密码；“下载并安装”会调用 SteamCMD。
4. 首次可保留“安装成功后设为下一局”和“部署副本添加入口日志探针”。选择下一局机器人难度，再点下载。账号缓存失效时，在顶部的一次性任务输入框补交密码或 Guard；手机批准在 Steam App 完成。
5. 等任务成功，确认库中有版本，下一局选择正确。下载期间不会替换当前运行的 bots 文件，不强制停掉对局。
6. 比赛结束后，点击运行概览里的“重启服务器”，或停服后再启动。显式重启会结束当前比赛。部署选中的固定版本后才启动游戏。
7. 玩家在自己的客户端 `connect 实际LXC地址:端口`，加入队伍。确认人类玩家到齐并已选边后，在机器人页点击“填充当前比赛空位”。不要在玩家进入前就填满槽位。
8. 查看服务端日志、脚本特征和实际 AI 行为。观察入口日志只能证明一个入口运行，不能证明全部 AI、玩家位置或整场对局正确。命令发出也不代表引擎接受，检查 unknown command / Lua error。

服务器仍可能在连接/等待玩家阶段推进选人；当前代码设置了 180 秒等待玩家超时，但没有实现真正的原生 Lobby ready 状态机。不要把这个超时当作“未点击开始就永远等待”的保证。

## 页面状态的含义

| 状态 | 能证明什么 | 不能证明什么 |
|---|---|---|
| 元数据核对成功 | 公开条目 App 570、机器人标签和基本类型符合要求 | 账号能下载、运行兼容 |
| 文件安装完成 | 指定 ID 返回成功，受管目录存在，脚本结构/大小/哈希通过 | 游戏已加载 |
| 下一局选择 | 已保存 ID、内容 SHA、难度和探针开关 | 当前比赛已换脚本 |
| 运行中脚本快照 | 这次启动使用的固定选择 | Lua 已执行或 AI 正常 |
| 检测到入口日志 | 本次进程的新探针出现在 hero_selection 的输出 | 完整 AI、位置和联机已验收 |

没有伪造下载百分比。任务日志显示实际 SteamCMD 输出。测试演示里的名称带“测试元数据”，不是从真实 Steam 下载的证明。

## 更新、回滚与停用

“下载最新版本”只下载/安装，不自动选中；当前运行的脚本完全不变。手动在版本下拉框选择，再点“设为下一局”。重复下载相同内容不会产生另一份版本。

“恢复上次选择”在上一选择和当前选择之间切换，仅作用于未来启动，不恢复正在进行的对局。“下一局停用自定义脚本”会在下次启动前恢复首次接管时保存的 bots 目录；该目录可能本来也是你装的自定义脚本，因此按钮不叫“保证恢复 Valve 默认 AI”。首次接管时没有 bots 目录，停用会移除面板部署目录。

意外崩溃的自动重试继续使用原进程的脚本快照，不会偷偷使用刚选中的下一局版本。显式重启、停服再开或代理重新启动后的自动开服会使用持久化的下一局选择。脚本版本固定，但运行时游戏配置仍以当前配置为准。

不能删除正在运行、已部署、下一局或上次选择引用的版本。每条目最多保留 12 版，最多 50 条目；清理库版本不删除 Steam 的下载缓存。源码升级不会自动删除库。

## 路径与版本

默认部署路径（实际以部署配置为准）：

```text
/var/lib/dota2/bot-library/
├── items/<Workshop-ID>/
│   ├── metadata.json
│   └── versions/<内容SHA-256>/
│       ├── scripts/                 # 不修改的下载归一化副本
│       └── version.json            # 文件清单、哈希、来源格式、忽略项
├── selection.json                  # 下一局和上次选择
├── deployment.json                 # 最近部署的记录
├── deployment-journal.json         # 仅在部署未完成时存在
└── incoming/                       # 解包临时目录

/srv/dota2/game/dota/scripts/vscripts/
├── bots/                           # 当前部署副本
├── .dota-panel-bots-old-<事务号>/    # 原目录或中断恢复备份
└── .dota-panel-bots-new-<事务号>/    # 部署同文件系统的临时副本
```

内容版本是归一化后“路径、字节数、每文件 SHA-256”的确定性哈希，不冒充 Steam manifest ID 或作者版本号。重新下载最新条目可以更新标题/时间而保持相同内容 SHA。

不要手工编辑受管 bots 或库里的版本。启动前会检查哈希，发现修改后拒绝覆盖，让你先保存重要文件。高级 Lua 定制的上传/编辑 UI 不在本版；使用脚本原始设置先验收。

## 下载与归档处理

实际核心命令固定为 `workshop_download_item 570 <数字ID> validate`，只接受 uint64 范围的字符串 ID，不接受 URL、合集或额外命令。元数据请求固定走 Valve HTTPS API；面板只用 HTTP 不意味着应把上游 Steam 下载也改成 HTTP。

要求 SteamCMD 返回**当前 ID**的成功记录，随后验证其实际内容目录。只搜索 SteamCMD、游戏目录与受管 Steam HOME 的预定 Workshop 缓存路径；不扫描整个文件系统，不把其他 ID 或旧缓存当作本次成功。`force_install_dir` 不作为 Workshop 必然落盘位置的保证。

支持：松散 Lua + 数据、ZIP、标准 Valve VPK v1/v2（含常规分卷）。识别唯一机器人根目录，保留脚本依赖层级，不额外套一层 ID 文件夹。多个独立脚本根、混合归档与 Lua、非机器人 App/标签、合集、加密/异常归档、纯编译资源不猜测处理。

大小限制：256 MiB 内容包/解包总量，32 MiB 单个解包文件，12000 个文件，VPK 树 8 MiB。路径穿越、绝对路径、链接、特殊文件、重复/大小写冲突均拒绝。仅部署 Lua 和固定数据后缀；本机二进制/安装脚本不执行，忽略项目记入版本元数据。无任意解包程序/URL/Shell 入口。

下载前库盘需至少 1 GiB 空闲；下载中任一受管数据盘少于 512 MiB 即中断。初装/游戏更新仍使用原有更高磁盘保护阈值。容量限制不是磁盘配额保证，Steam 缓存和残留内容仍占空间。

取消在 SteamCMD 等待/下载与逐文件检查处生效；元数据请求最多等待约 20 秒才看到取消。文件已原子存入版本库后恰好取消，可能留下一个已安装但未选中的版本；不会改掉运行中脚本，也不会把任务伪报为成功。代理异常退出后未自动重试下载，incoming 残留可在确认没有任务后人工清理，别删除部署备份。

## 当前 Linux Dedicated 加载方式与限制

本版在启动前复制脚本到本地 `game/dota/scripts/vscripts/bots`。启动参数包含：

```text
-allow_no_lobby_connect
+sv_lan 1
+dota_bot_practice_script 0
+dota_bot_practice_difficulty <0..3>
+dota_bot_set_difficulty <0..3>
+dota_wait_for_players_to_load 1
+dota_wait_for_players_to_load_timeout 180
...其他既有配置...
+map dota
```

仅选中自定义脚本时才附加机器人参数；允许无大厅连接的参数适用于这个 LAN 直连方案。以上是已编码、测试了参数顺序的加载策略，**还没有证明这些控制变量在当前 Linux Dedicated 中均有效**。如游戏报未知变量、入口无输出或仍使用默认机器人，必须记录真实构建与日志，调整兼容层后重测，不能把“拷贝成功”当作方案已跑通。不会为了隐藏问题自动切换默认 AI、修改授权库或静默启用作弊。

难度下拉是控制台整数 0/1/2/3（简单/中等/困难/不公平），不是官方 GC 的枚举；还没有从房间映射双方难度，也不保证作者脚本使用这个控制值。双方不同机器人尚未支持。

入口探针可关闭。开启且存在 hero_selection.lua 时，仅部署副本开头插入本次随机标记的 print，下载版本不改；每次启动重新生成标记，旧局日志、普通控制台 echo 不算。依赖这个探针的逻辑未在真实 Lua VM 执行，测试使用模拟进程生成标记。日志证明的是执行入口，不是防伪 attestation，第三方脚本本身拥有游戏 Lua 运行权限。

天地星AI 的房间槽位依赖/模式限制需要独立验收。首次用普通 All Pick，不宣称支持队长模式或任意站位复原。原生房间的配置不能仅凭玩家 connect 自动带到服务器。

## 安全、备份与排错

HTTP 免面板认证是用户明确要求。获准 LAN 访问者均可管理，Steam 密码/Guard 在本地网络上仍是明文；只在可信 LAN 用，不开公网转发。只安装信任作者的 Lua；文件校验不是 Lua 安全沙箱。游戏和 SteamCMD 使用非 root steam 用户，代码 root-owned，容器非特权。

“配置备份”仍只备份服务器 JSON，不包含机器人库、下载缓存、部署目录或游戏存档。完整保留机器人版本和原始备份需离线/停服 PVE 备份，尤其要保护其中的 Steam 登录缓存。

常用只读排错：

```bash
# 在 LXC 内执行
dota-cli bots
dota-cli status
dota-cli jobs
dota-cli logs --name server
systemctl status dota-agent dota-panel nginx --no-pager
journalctl -u dota-agent -u dota-panel -n 150 --no-pager
```

元数据失败先查出站 DNS/HTTPS；授权失败由用户补交；下载成功但目录不识别保留实际路径；解包失败保留格式/文件名而非发送整个 Steam HOME；哈希错误保留手工修改；恢复日志异常则停服并先备份 bots、同级 old/new 与 bot-library，按 CODEX_WORKSHOP_HANDOFF 检查。不要删除保护文件后强行启动。

详细设计和验收依据见 WORKSHOP_SOURCES.md、WORKSHOP_TEST_REPORT.md、CODEX_WORKSHOP_HANDOFF.md。
