# 安全边界

本版面向单管理员、受信任 LAN、单实例专用 LXC。不是公网多租户游戏托管平台，未经过第三方审计。

## 默认保护

非特权 LXC、nesting 关闭，应用与代理均非 root；无 sudo/no arbitrary shell/no Docker socket；root-owned 应用文件只读。游戏与下载发生在 steam 用户目录，面板不能直接改宿主资源。

按用户要求，面板使用 HTTP 且不校验网页密码。Nginx LAN allow/deny、单 CT PVE 规则、Origin/CSRF、HttpOnly/Strict Cookie、Host 白名单与固定 API 路径仍然生效。[S4][S5] HTTP 不加密网络传输，因此必须限制在受信任 LAN，禁止公网转发。数据中心/节点防火墙未启用时，不应宣称 CT 层规则一定生效。

Steam 密码/Guard 不出现在 argv、配置、持久任务记录和应用日志中；仅在内存与交互 PTY 中使用。不能承诺 Python 字符串物理擦除。Valve SteamCMD 自己的缓存、日志、崩溃转储可能包含敏感数据，必须限制访问；本项目不会导出这些原始文件。

日志写盘前脱敏、限制长度并轮转；诊断隐藏启动参数中的游戏密码并排除 Steam 缓存。未知格式的上游 token 不保证均可自动识别，发给第三方前仍需人工复查。

## 管理建议

仅从受信任 LAN 使用面板。不要公开转发面板/游戏端口，不开启调试服务器在 0.0.0.0 监听，不把代理 socket chmod 777，不以 root 跑 SteamCMD。

使用专门的 Steam 账号做服务器维护是一种权限隔离选择，但其 App 570 权限、会话策略和 Steam Guard 仍须按 Valve 要求验证。任何账户密码都不需要提交给开发接手者或写进 ZIP。

完整 PVE 备份包含 Steam 账号缓存等敏感数据；配置备份也可能含游戏连接密码。为存储和传输设置访问限制。

## 已知范围限制

1. 游戏与 SteamCMD 共用 steam 用户，意味着假如游戏进程被攻破，该用户自己的 Steam 缓存也可能受影响；网页与 steam 用户隔离并不能消除此风险。保持仅 LAN、及时维护，必要时进一步把下载账号与游戏账号分离。
2. 游戏资源由 Valve 下载器动态取得，Ubuntu 包由 apt 仓库取得；代码 ZIP 不对未来依赖做逐个内容锁定。安装器可配置预期 SHA-256，不填写时仅记录实际安装器 hash，不能把它当作独立来源验证。
3. HTTP 面板不提供传输加密或网络身份验证；LAN 内存在恶意设备时应通过独立反向代理增加 HTTPS/认证，或隔离管理网段。
4. 本地 root/PVE 管理员仍能读取进程内存、缓存与配置，属于本项目信任边界内。
5. 单实例的防抖/任务锁不用于分布式多个代理；运行代理使用 lifetime flock 拒绝本地第二实例。

报告问题时提供脱敏诊断和测试步骤，不提供密码、验证码或整个 Steam home。
