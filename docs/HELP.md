# 使用帮助

这是管理你自己的 Dota 2 LAN 服务器的面板，不是 Steam 客户端，也不是 Valve 官方匹配服务。当前服务器固定使用天地星 AI，一名真人对战 AI。面板使用 HTTP 80 端口，游戏端口以概览页的连接命令为准。

## 玩一局的流程

1. 在"Windows 客户端资源"页下载安装包，退出 Dota 2 后运行，选择 Steam 目录。服务器每次发布新版本后都要重新安装。
2. 打开 Dota 2，在控制台输入概览页显示的 `connect` 命令。
3. 在游戏内"游戏选项"窗口选择双方 AI 难度、人数等参数，点"确认设置并开始"。选人和出兵前时间固定为 45 秒。
4. 如果屏幕顶部显示"客户端资源版本与服务器不一致"，说明本机资源过期：打完或退出后重新安装客户端资源。

## 游戏内对局工具

比赛开始后，屏幕顶部的对局工具提供以下操作（除重启外都需要服务器开启作弊）：

| 功能 | 说明 |
|---|---|
| restart：摧毁本局并重启一局游戏 | 需在 5 秒内再点一次确认；只有房主可用。服务器会完整重启，约 30 秒后重新输入 connect 命令 |
| 刷新 / 重置英雄 | 恢复生命、魔法并刷新冷却；重置会先复活并回到泉水 |
| 金币、等级 | 自己 +1000 金币；己方或对方 AI 各 +1000 金币或 +1 级 |
| 添加技能 | 输入框可填任意技能内部名称，非先天技能需手动加点；"快捷技能（36）"在右侧展开第二栏（每行 3 个，窗口随之加宽，不出现滚动条），36 个先天技能一键添加并直接满级；已拥有的显示 ✓，再点一次即移除；鼠标悬停显示所属英雄 |
| 删除该技能 | 删除输入框里填写的技能。只能删除通过面板添加的技能；手动加过点的会返还技能点 |
| 基础攻击间隔 | 按钮在初始值 ±0.3 秒内调整；超出范围时按钮会先回到最近的边界 |

聊天指令：`-gold 数值`、`-lvlup 级数`、`-refresh`、`-respawn`，以及 `-basetime 秒数`（0.1～10 秒，不受按钮范围限制）。

## 收益规则

- 双方基础倍率：比赛开始后 5 分钟内为 1×，5～15 分钟线性升到 1.5×，之后保持。
- AI 每死亡一次加一层（最多 9 层），额外加成为 层数×(层数+1)/20；AI 击杀英雄时减 3 层。AI 的总倍率不超过 5×。
- 这些数值集中在 `addon/lan_dota/game/scripts/vscripts/lan/bot_comeback.lua` 的 `RULES` 表里。


## 1. HTTP 免登录与 Steam 授权

本面板无需管理员账号或密码，直接访问 `http://LXC的IP/`（面板端口默认 80）。不启用 HTTPS，不生成证书，也不会跳转到登录页。IP 建议静态或 DHCP 保留。

SteamCMD 的授权不同于面板登录：Steam 登录账号、Steam Guard 或手机批准仍按 Valve 要求完成。HTTP 会明文传输你输入的 Steam 凭据，只能在信任的 LAN 使用；不要把密码发给开发接手者。

LAN 白名单内任何人都可管理服务器并读取配置/日志。白名单、Host、Origin、JSON 与自动 CSRF 令牌检查继续保留；浏览器自动取得令牌，不需要用户登录或输入任何令牌。

## 2. 首次开服

打开面板 → SteamCMD → 输入 Steam 登录名/密码 → 测试登录/授权 → 完成 Steam Guard 或手机批准 → 安装 Dota 2（含校验） → 等待任务成功 → 检查服务器配置 → 启动服务器 → 在另一台设备的 Dota 2 控制台 connect 到 CT 的 IP:游戏端口。

安装会从 Valve 下载 App 570 Linux 内容，ZIP 不含游戏。不要依赖匿名下载可用。初始环境安装不下载完整游戏，也不自动开服。客户端安装/更新、Steam 授权与 LAN 建服是不同步骤，不能据此保证完全断网可玩。

```text
connect 192.168.1.70:27015
```

这是示例 IP；使用概览页提供的连接命令。如果设置了游戏连接密码，按客户端提示输入或在客户端控制台先设置对应 password。先验证地图、选人和实际对局，再把它当作可用服务器。

## 3. 页面说明

| 页面 | 用途 |
|---|---|
| 运行概览 | 启动/停服/重启，连接命令，游戏资源版本（源码 / 已部署 / 客户端包是否一致），进程与资源状态 |
| Windows 客户端资源 | 下载与服务器同版本的客户端安装包（EXE 自动安装或 ZIP 手动安装） |
| SteamCMD | 授权、安装、更新、校验、一次性密码/Guard 补交、任务取消 |
| 任务记录 | 查看实际完成/失败/取消/中断；点击任务名看日志 |
| 日志与控制台 | 游戏/代理/历史任务日志；受限 status/pause/say |
| 服务器配置 | 名称、端口、地图、模式、游戏密码与自动开服/有限崩溃重试 |
| 备份与诊断 | 配置快照、停服恢复、下载快照、脱敏诊断 |

页脚显示面板版本、代码提交号和部署时间，可据此确认服务器上运行的是哪次提交。

“代理在线”仅表示管理链路可达；“进程运行中”不代表建图完毕；“发现 UDP 监听”不是客户端联机测试。面板没有伪造的玩家数或下载百分比。

## 4. Steam Guard 怎么提交

已经有验证码时可随登录提交。SteamCMD 运行中要求验证码/密码时，顶部出现一次性输入框，输入后点击提交一次性输入。页面刷新不会结束等待任务；等待输入最多 5 分钟，超时后重新发起。手机批准需在你的 Steam 手机客户端确认，面板不会替你批准，也不绕过 Steam Guard。

应用不保存 Steam 密码/验证码，不放进进程命令行或应用日志。Valve 自己可能写登录缓存，后续更新有时可留空密码复用，有时需要重新验证。输入从页面清除不等于可证明的浏览器/系统内存擦除。

当日 SteamCMD 提示发生变化、网页不能识别时，按 DEPLOYMENT.md 的控制台首次授权流程处理；不要关闭 Steam Guard。先停服/结束任务，不能网页和控制台同时运行两个 SteamCMD。

## 5. 正常更新

比赛结束后停止服务器，等停止任务成功，再点击更新。或明确勾选“允许本次维护先停止正在运行的服务器”。“成功后恢复原先运行中的服务器”仅恢复任务开始时已在线的实例；原本没开服不会因此被自动开服。

一次只能运行一个变更任务。正在更新时不能启动游戏或再次更新。失败后检查任务日志；失败/取消保留维护保护标记，成功更新或校验后才解除。不要手工删除标记规避检查。

validate 校验/修复可能覆盖 Valve 管理文件的手动改动。你在面板保存的配置位于独立 JSON，正常更新不会改掉它。没有自动定时停服更新，避免比赛期间中断。

## 6. 启停与自动恢复

点击停止会先发送 quit，超时后终止本代理创建的进程组。点击重启会中断当前对局。页面关闭、只重启网页后端都不停止服务器；重启运行代理或整个 LXC 会停止游戏与 SteamCMD。

自动开服默认关，可在配置中启用；要求安装入口存在且无未完成维护。崩溃自动重试默认开，10 分钟最多 3 次，超过后停下让你排错。它不是无限循环守护。

## 7. 配置与局域网

sv_lan 固定 1。不提供任意 Shell、可执行文件路径或 RCON 输入。改端口须同步 PVE 防火墙，配置保存本身不改宿主规则。默认 map=dota，game_mode=1；0 表示不强制模式。模式编号、机器人和暂停命令是否适配当前版本要以游戏日志为准。

-insecure 和作弊开关默认关。-insecure 是关闭服务器 VAC 的选项，不是绕过 Steam 登录或免费许可的方法。不要为排查连接问题无差别开启所有选项。

跨 VLAN 时需要网络可达、明确的白名单以及游戏本身允许连接；Wi-Fi AP 隔离也可能阻止设备互通。面板能打开并不证明游戏 UDP 路径正常。

## 8. 配置备份和恢复

修改配置、维护前自动保存快照，也可手动备份；最多保留 20 份。恢复前须停服，会再备份当前配置。下载文件可能含游戏连接密码和 Steam 账号名；不含 Steam 密码、登录缓存或游戏资源。

配置恢复不回滚 Dota 2 版本，不恢复正在进行的比赛。需要全量恢复时使用 PVE 备份，且应保护其中的 Steam 缓存等敏感数据。

## 9. 常用恢复命令

```bash
# PVE：270 应换成自己的 CTID
pct enter 270

# 以下为 LXC 内部命令
dota-cli status
dota-cli jobs
dota-cli logs --name server
dota-cli stop
systemctl status dota-agent dota-panel nginx --no-pager
journalctl -u dota-agent -u dota-panel -n 150 --no-pager
```


## 10. 资源和支持边界

配置固定 6 vCPU / 6 GiB / 250 G，另有默认 1 GiB swap 额度；不能保证所有模式和人数在 6 GiB 内稳定运行。通过 cgroup/PVE 检查 OOM，而不是只凭平均占用判断。

初装空闲磁盘阈值 100 GiB、后续更新 20 GiB，是保护性下限，不是对未来 Steam 内容大小的保证。日志有限轮转，不会主动删除游戏下载目录来省空间。

需要接手排查时，导出“诊断 JSON”，自己检查无秘密再交给接手者。不要发送 Steam 密码/验证码、整个 Steam home 或完整 PVE 备份。完整的现场验收标准在 ACCEPTANCE.md；更新代码和发布游戏资源的步骤见 RELEASE.md。

## 11. CPU / 内存实时监控

概览页每约 2 秒刷新总 CPU、有效配额、每个可见核心占用、内存总量/上限/占用率、工作集、缓存、Swap 与累计 OOM。趋势显示当前页面最近 2 分钟，刷新页面清空；后台标签页暂停，返回恢复。

6 核总 CPU 为 100% 的满量程；单核满载约占总量 16.7%。内存主要比例包含 cgroup 已计费缓存，工作集另外显示，不要把工作集当作全部物理占用。

总量优先读取可见 cgroup 挂载根，每核取 /proc/stat 可见视图。LXCFS 或宿主视图的来源在图下标明；每核不保证是仅 Dota 2 或仅本容器任务的精确逐核归属。未检测到 LXCFS 会提示，不会伪造六个核心或 6 GiB 上限。

首次 CPU 采样、计数重置、数据不可读时显示 —。断线会清除实时数值并自动重试；相同样本超过 6 秒不变化会提示过期。没有有效数据时不显示 0% 冒充正常空闲。监控是只读，不修改 CT 资源，也不会运行特权宿主命令。

详细公式、API 与现场对照步骤见 MONITORING.md；在 LXC 可执行 dota-cli metrics 查看同一数据。
